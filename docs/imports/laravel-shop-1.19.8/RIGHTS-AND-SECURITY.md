# وضعیت مجوز استفاده و ریسک‌های امنیتی اولیه

## ارزیابی مجوز (هنوز تأیید نشده)

- بستهٔ ارسالی راهنمای `help.pdf` دارد که پیش‌نیازهای نصب، SSL و الزامات Laravel/PHP را توضیح می‌دهد؛ در آن مجوز صریح بازنشر سورس اختصاصی به دست نیامد.
- `composer.json` اسکریپت عبارت `"license": "MIT"` دارد، اما `name: laravel/laravel` و `description: The Laravel Framework` است؛ این داده به تنهایی ثابت نمی‌کند تمام کدهای اختصاصی فروشگاه، قالب، تصاویر و افزونه‌ها زیر MIT قابل بازنشرند.
- LICENSE محصولِ مستقل از LICENSE وابستگی‌های vendor در بسته یافت نشد. حقوق خرید، کپی در مخزن عمومی، استفاده در چند نصب یا فروش مجدد مشخص نیست.
- مالک باید فاکتور/لایسنس/متن قرارداد یا تأییدیهٔ عرضه‌کننده را بررسی کند. مدرک خرید یا اطلاعات محرمانه در GitHub عمومی منتشر نشود.
- **تا روشن شدن این موضوع، فقط مستندات و دادهٔ فنی غیرمحرمانه در GitHub ثبت شده‌اند؛ کد اختصاصی Laravel Shop، آرشیو یا دارایی‌هایش هنوز وارد مخزن ویرا نشده است.**

## ریسک‌های قابل بررسی قبل از اجرا

1. در `.env.example` سورس کلید `APP_KEY` نمونه از پیش مقداردهی شده است. این فایل و کلید هرگز جایگزین .env ویرا نشوند؛ کلید فعلی ویرا بدون نیاز نباید تغییر کند.
2. مسیر و منطق `loginAsUser` / impersonation مدیر در کنترلرهای قدیمی باید پیش از فعال‌سازی تحت بررسی مجوز، ثبت لاگ و محدودیت امنیتی قرار گیرد.
3. installer / updater / backup / file-manager / API keys / debugbar و public storage باید از نظر دسترسی، افشای فایل، آپلود و اجرا بررسی شوند.
4. وابستگی‌ها و فایل‌های `vendor/` در اسکریپت قدیمی لزوماً مناسب Laravel 13 نیستند؛ نسخه و مجوز هر کتابخانه باید مستقل بررسی شود.
5. هیچ Migration، Seeder یا `artisan` از بسته ناشناس در دیتابیس اصلی اجرا نشود. اجرای نخست فقط در محیط ایزوله با دیتای ساختگی، بعد از تأیید مجوز و ممیزی امنیت باشد.
6. هیچ credential واقعی، فایل `.env`، پایگاه‌داده یا فایل ZIP سورس به مخزن عمومی commit نشود.

**این یک ارزیابی ساختاری و اولیه است، نه ممیزی امنیتی کامل یا نظر حقوقی قطعی.**
