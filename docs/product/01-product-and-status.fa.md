# ۱. محصول، تصمیم‌ها و وضعیت واقعی

## هویت و هدف

نام کاری محصول **ویرا — یکپارچه با جهش** است. مالک محصول ابوالفضل یوسفی از تیم جهش است. جهش خدمات طراحی سایت، نرم‌افزار و پشتیبانی ارائه می‌کند. هدف، ساخت محصولی اختصاصی و قابل توسعه برای عرضه به کسب‌وکارهای مختلف است؛ مالک محصول فعلاً توسعه، ارتقا و پشتیبانی را خودش مدیریت می‌کند.

مخاطب اصلی، فروشگاه دارای کالای فیزیکی و فروش حضوری است که سایت فروشگاهی و مدیریت یکپارچهٔ مشتری، کالا، موجودی و فروش می‌خواهد. محصول باید عمومی باشد، ولی در شروع همهٔ پیچیدگی‌های تمام اصناف را پوشش نمی‌دهد.

«مشتری محصول ویرا» یعنی فروشگاهی که نرم‌افزار را از جهش می‌گیرد. «مشتری فروشگاه» یعنی خریدار نهایی که اطلاعاتش در Customers ثبت می‌شود. این دو مفهوم نباید در مدل داده یا بحث چندمشتری اشتباه شوند.

## تصمیم‌های مورد توافق

- یک پروژهٔ Laravel با معماری Modular Monolith شامل ERP، CRM، صندوق و سایت اختصاصی.
- سایت وردپرسی نیست؛ سایت و پنل رابط مستقل دارند و از منطق مشترک استفاده می‌کنند.
- ارتباط داخلی سایت با هسته نیازمند HTTP API جدا نیست؛ اتصال خارجی ممکن است API و webhook لازم داشته باشد.
- قابلیت‌ها ماژولار و برای هر نصب قابل انتخاب باشند؛ خاموش کردن ماژول، اطلاعاتش را حذف نکند.
- مشتری، کالا، سفارش و موجودی یک مرجع اصلی داشته باشند؛ سایت و صندوق نسخهٔ جدا از این داده‌ها نسازند.
- رابط فارسی، راست‌چین، واکنش‌گرا، ساده و حرفه‌ای، با فونت رایگان وزیر.
- Blade و Livewire مبنای رابط باشند؛ Alpine برای تعامل‌های سبک استفاده شود.
- استفاده از پکیج آمادهٔ مناسب مطلوب است؛ منطق اختصاصی محصول با مرزبندی روشن نوشته شود.
- مدیریت اشتراک و پرداخت دوره‌ای فعلاً اولویت نیست و می‌تواند توافقی و دستی باشد.

## مدل استقرار فعلی

فعلاً **یک کسب‌وکار در هر نصب** داریم. SaaS چندمجموعه‌ای، جداسازی tenant، مدیریت اشتراک و محدودیت مصرف پیاده‌سازی نشده‌اند. فعال بودن یک ماژول در نصب با مجوز کاربر متفاوت است. در آینده اگر میزبانی چند کسب‌وکار در یک نصب لازم شد، طراحی مستقلی برای جداسازی داده، فایل، کش، صف و عضویت نیاز دارد.

## واقعاً چه چیزی ساخته شده است؟

- Laravel 13، Livewire 4، Fortify و ابزارهای ساخت فرانت‌اند نصب‌اند.
- ورود و خروج کارکنان، محدودسازی تلاش ورود و ساخت مدیر از طریق `vira:owner` وجود دارد.
- نقش‌های `owner` و `operator` و مجوزهای پایه با Spatie تعریف شده‌اند. مدیریت تصویری کامل کاربران و نقش‌ها هنوز ساخته نشده است.
- پنل واقعی Blade/Livewire با سایدبار جمع‌شونده، تم بنفش/آبی/رز، حالت روشن/تیره و فونت محلی وزیر وجود دارد.
- داشبورد آغازین تعداد کاربران، دسترسی ماژول‌ها و حداکثر پنج رویداد اخیر را نشان می‌دهد؛ گزارش واقعی فروش نیست.
- صفحهٔ وضعیت ماژول‌ها فقط خواندنی است؛ فعال‌سازی فعلی از تنظیمات یا فرمان ماژول انجام می‌شود.
- پکیج ثبت فعالیت نصب است و ایجاد مدیر رویداد ثبت می‌کند؛ ثبت جامع تمام عملیات هنوز وجود ندارد.
- پکیج فایل و migration مربوط به آن نصب است؛ مدیریت فایل تجاری و مجموعه‌های فایل هر ماژول ساخته نشده‌اند.
- صفحهٔ عمومی سایت، صفحهٔ معرفی/آماده‌سازی است؛ فروشگاه عملیاتی نیست.
- کنترل وابستگی ماژول‌ها و محدودیت سمت سرور وجود دارد.
- دیتابیس نصب اولیه SQLite است. راهنمای MySQL موجود است؛ انتقال داده و آزمون عملی MySQL هنوز انجام نشده است.

هشت ماژول فعلی: `Core`، `Customers`، `Catalog`، `Inventory`، `Sales`، `Crm`، `Pos` و `Storefront`.

به‌جز هسته و رابط آغازین، صفحات این ماژول‌ها فعلاً صفحهٔ اعلام آماده‌سازی هستند. **CRUD مشتری، کالا، انبار، سفارش، فاکتور، درگاه، صندوق عملیاتی و CRM هنوز ساخته نشده‌اند.**

## سابقهٔ بررسی

در تحویل پایه، ۱۱ آزمون با ۴۶ assertion، ساخت فرانت‌اند، بررسی مرورگر و بررسی GitHub Actions روی PHP 8.3 و 8.4 موفق بوده‌اند. رفتارهایی مثل مسدود شدن پنل برای مهمان، رد کاربر بدون مجوز، خاموش شدن CRM بدون قطع صفحهٔ سایت، وابستگی ناقص، ورود/خروج و جلوگیری از بازنویسی حساب مدیر آزمون شده‌اند.

این سابقه مربوط به نسخهٔ پایه است؛ اجرای فعلی سرور یا سلامت تغییرات آینده را تضمین نمی‌کند. چت بعدی باید وضعیت جاری مخزن و بررسی‌های متناسب با تغییر جدید را دوباره ببیند.

## دامنهٔ عمومی آغازین و موارد آینده

نسخهٔ آغازین عملیاتی، هدفش کالای ساده و دارای تنوع، چند انبار، فروش آنلاین و صندوق متصل به اینترنت است. سریال کالا، تاریخ انقضا، فروش وزنی، بچ تولید، صندوق آفلاین، حسابداری کامل، حقوق‌ودستمزد و تولید صنعتی فعلاً قابلیت آینده‌اند. انتخاب دقیق نسخهٔ اول هر ماژول هنگام شروع همان مرحله نهایی می‌شود.
