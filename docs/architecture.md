# تصمیم‌های معماری ویرا

## یک برنامه، مرزهای مشخص

یک مخزن و یک پروژهٔ Laravel؛ رابط پنل و سایت جدا، منطق کسب‌وکار مشترک. ارتباط داخلی با فراخوانی Actions و Contracts انجام می‌شود. API شبکه‌ای برای ارتباط سایت همین برنامه با هسته ضروری نیست؛ webhook درگاه و اتصال‌های خارجی بعداً مسیر و احراز هویت مستقل خواهند داشت.

## جهت وابستگی

Core ← Customers ← Crm

Core ← Catalog ← Inventory

Customers + Inventory ← Sales ← Pos / Storefront

خاموش کردن CRM نباید خرید سایت یا صندوق را مختل کند. هویت مشتری در Customers است، نه CRM. `ModuleAccess` برای وابستگی غیرفعال یا چرخهٔ وابستگی، دسترسی را رد می‌کند. مسیرهای پنل، علاوه بر فعال بودن ماژول، مجوز کاربر را نیز بررسی می‌کنند.

## مدل مشتریان محصول

فعلاً هر نصب برای یک کسب‌وکار است. پشتیبانی از چند مجموعهٔ مستقل در یک دیتابیس، اشتراک و محدودیت مصرف ساخته نشده است. اضافه کردن آن‌ها مستلزم طراحی جداگانهٔ جداسازی داده، فایل، کش، صف و عضویت کاربر است.

## مالکیت داده و مسیر فروش بعدی

هر ماژول مالک جدول‌ها و قواعد خودش است. کالاهای متنوع در Catalog، گردش و رزرو در Inventory، سفارش و صورتحساب در Sales قرار می‌گیرند. سایت و صندوق نباید منطق مستقل کسر موجودی داشته باشند. برای مسیر خرید بعدی، تراکنش، جلوگیری از فروش بیش از موجودی و ثبت غیرتکراری پرداخت ضروری‌اند.

## معماری ویجت‌ها و سکشن‌های معرفی سایت

رجیستری ویجت در Core فقط کلید، عنوان، ماژول مالک، مجوز، نمای Blade و resolver را ثبت می‌کند. دادهٔ هر ویجت را ماژول مالک فراهم می‌کند و Registry قبل از فراخوانی منبع داده، دسترسی کاربر و موجود بودن ماژول را بررسی می‌کند. چیدمان بر اساس شناسهٔ کاربر ذخیره می‌شود؛ تنظیمات ویجت‌های حذف‌شده/غیرفعال حذف خودکار ندارند. ویجت فروش واقعی تا زمان تکمیل Sales وجود ندارد.

Storefront مالک سکشن‌های عمومی قابل مدیریت Hero، Features و CTA است. مقادیر پیش‌فرض در کد باقی می‌مانند؛ تنظیمات معتبر ثبت‌شده در دیتابیس روی آن‌ها اعمال می‌شوند. مسیر مدیریت فقط در پنل با مجوز `storefront.manage` قابل دسترسی است. این بخش صفحه‌ساز عمومی یا فروشگاه عملیاتی نیست.

## پول و تاریخ

مبالغ پولی باید واحد صریح داشته باشند. پیشنهاد دامنهٔ مالی، ذخیرهٔ عدد صحیح ریال و تبدیل کنترل‌شده به تومان در نمایش است؛ مدل‌های تجاری هنوز ساخته نشده‌اند. `brick/money` برای دقت محاسبات در دسترس است. تاریخ‌ها UTC ذخیره و برای کاربر با Asia/Tehran و جلالی نمایش داده می‌شوند.

## مرز خرابی

ماژولار بودن کد تضمین جداسازی خرابی نیست. خطای bootstrap، دیتابیس یا کمبود منابع می‌تواند همهٔ بخش‌ها را تحت تأثیر قرار دهد. در شروع، صف دیتابیسی استفاده می‌شود؛ صف‌های پیشنهادی `critical`، `default`، `notifications` و `reports` هستند. روی سرور واقعی، گزارش‌ها worker و منابع مجزا می‌خواهند. نام جدا برای صف، به‌تنهایی جداسازی منابع ایجاد نمی‌کند.
